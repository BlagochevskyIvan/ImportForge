# ImportForge — фронтенд

Next.js 16.4.2 (App Router), React 19.3.0, TypeScript. Только встроенные React Hooks, fetch и обычный CSS внутри `components/Styles.tsx`. Tailwind и его loader удалены; новые библиотеки не добавлялись.

## Запуск

Нужен Node.js 20.9+ и работающий FastAPI с PostgreSQL. Не запускайте Next.js как статический экспорт: прокси `/api` требует сервера Next.js.

В корне репозитория, при первом запуске:

```bash
make install
make env
make db-up
make keys
make migrate
make run
```

`make env` сохраняет существующий `.env`, `make keys` сохраняет существующие ключи. Проверьте настройки базы в `.env`; для `make db-up` нужен запущенный Docker. Эти команды относятся к обычной базе разработки, а не к временной QA-базе из проверки ниже.

Во втором терминале:

```bash
cd /Users/ivanblagocevskij/Programs/Projects/ImportForge/src/web
npm ci
npm run dev
```

Откройте [ImportForge](http://localhost:3000). Для другого адреса API задайте `API_BASE_URL` в `src/web/.env.local` по примеру `.env.example`, без завершающего `/`. Перезапустите Next.js после изменения; для production пересоберите приложение.

`API_BASE_URL` читает серверная конфигурация Next.js, клиент вызывает относительный `/api/...`. Бэкенд должен разрешать фактический адрес фронтенда в `AUTH_ALLOWED_ORIGINS`. По умолчанию разрешены localhost и 127.0.0.1 на порту 3000. Если Next.js выбрал порт 3001, добавьте его origin в настройки FastAPI и перезапустите FastAPI либо освободите порт 3000. Не смешивайте localhost и 127.0.0.1 во время работы: это разные хосты для cookie.

Для production:

```bash
npm run build
npm run start
```

На HTTPS установите `REFRESH_COOKIE_SECURE=true` в конфигурации FastAPI и точный frontend origin в `AUTH_ALLOWED_ORIGINS`. В контейнере `API_BASE_URL` должен указывать на доступный Next.js адрес FastAPI, обычно имя сервиса, а не loopback чужого контейнера.

- `components/SupplierDetail.tsx` — загрузка карточки и конфига после проверки сессии. `SupplierConfigForm.tsx` — выбор и сохранение настроек; `CsvUpload.tsx` — файл, валидация, multipart-загрузка и подтверждение.
- `components/Header.tsx`, `AccountLink.tsx` — серверная навигация и маленькая клиентская ссылка по состоянию сессии.
- `hooks/useAuth.tsx` — Context/Provider с профилем и восстановлением сессии.
- `lib/api.tsx` — DTO, fetch, HTTP-ошибки, обновление токена и конечный повтор при 401.
- `components/Styles.tsx` — обычный `<style>` с CSS и media queries, без CSS-in-JS библиотеки.
- `next.config.ts` — прокси к существующему FastAPI. Это служебное исключение из правила `.tsx`, как и генерируемый `next-env.d.ts`.

## Сессия и ограничения

Access JWT хранится только в памяти вкладки. Refresh хранит браузер в HttpOnly cookie, которую уже выдаёт FastAPI. При загрузке: refresh → /me → профиль в Context. Защищённые запросы передают Bearer JWT, а при 401 пробуют один refresh и один повтор. Одновременные запросы внутри вкладки используют один Promise; вкладки с Web Locks последовательно меняют refresh cookie. BroadcastChannel уведомляет о входе/выходе, без передачи токенов.

Если Web Locks или BroadcastChannel отсутствуют, внутривкладочная логика и проверки API остаются, но межвкладочная координация ограничена. Web Locks требует подходящего secure context, в том числе работает на loopback. Клиентский редирект не является серверной защитой: FastAPI проверяет JWT, активность и владельца при каждом защищённом запросе. В HTML Dashboard нет персональных данных.

Logout отзывает refresh, но выпущенный access JWT остаётся действителен до exp — это свойство текущего бэкенда. Ошибка сети при logout отображается как неподтверждённый выход; клиент не обещает отзыв серверной сессии. HttpOnly не устраняет XSS, только закрывает прямое чтение cookie JavaScript-кодом.

Список использует offset/limit и сортировку API по ID: на странице 20 записей, запрос 21-й определяет наличие следующей страницы. После создания открывается карточка нового поставщика; существующего можно выбрать кнопкой «Выбрать» или по названию в таблице. Автоповтора POST при сетевом сбое нет: нельзя исключить, что сервер уже записал поставщика.

## Поставщик → конфиг → CSV

1. На `/dashboard` создайте поставщика или выберите существующего.
2. В карточке выберите сохранённый конфиг, шаблон CSV с запятой / точкой с запятой / табуляцией либо JSON-файл. Доступны UTF-8, UTF-8 с BOM и Windows-1251.
3. Укажите точные названия колонок исходного CSV для `sku`, `name`, `price` и нажмите «Сохранить конфиг». Сохраняется один текущий конфиг поставщика.
4. Выберите непустой `.csv` размером до 20 МиБ и нажмите «Загрузить CSV». При изменении настроек сначала сохраните их либо верните сохранённый конфиг.
5. После ответа сервера появятся имя файла, UUID и статус «загружен». Это сохранение исходного файла; обработчик преобразования CSV ещё не реализован.

Форма показывает, сохранены ли текущие настройки. «Отменить изменения» возвращает
последний успешно сохранённый конфиг. «Скачать сохранённый JSON» экспортирует
серверную версию с обёрткой `config_data`; файл можно снова выбрать через
«Выбрать JSON-конфиг» и сохранить для этого или другого поставщика.
JSON ограничен 64 КиБ. Неизвестные параметры, `null` вместо кодировки/разделителя
и одинаковые названия исходных колонок отклоняются; отсутствие кодировки и
разделителя использует UTF-8 и запятую, как в API.

Пример JSON-конфига (также принимается объект с обёрткой `config_data`):

```json
{
  "delimiter": ";",
  "encoding": "utf-8",
  "column_mapping": {"Код": "sku", "Наименование": "name", "Цена": "price"}
}
```

Контракты FastAPI:

- `GET /suppliers/{id}` — карточка владельца.
- `GET /suppliers/{id}/config` — сохранённый конфиг, `null`, если у доступного поставщика его пока нет.
- `PUT /suppliers/{id}/config` — полная замена `{ "config_data": ... }` через существующий PostgreSQL upsert. Другой владелец получает 404.
- `POST /imports` — multipart с полями `supplier_id` и `file`. Bearer JWT обязателен; до обращения к хранилищу проверяются поставщик и наличие конфига. В БД сохраняются поставщик и снимок настроек на момент загрузки. Ошибка записи метаданных вызывает попытку удалить загруженный объект из S3.

В `lib/api.tsx` JSON-запросы и `FormData` используют общий механизм JWT. Для `FormData` заголовок `Content-Type` задаёт браузер вместе с multipart boundary; тайм-аут загрузки — 120 секунд. Сетевые ошибки не вызывают автоматический повтор POST.

Для запуска обновлённой версии примените миграции из корня (`make migrate`) и перезапустите API. Миграция `d38f04e271ab` добавляет связь файла с поставщиком и снимок конфига. Старые файлы сохраняются с пустыми новыми полями: их владельца невозможно определить автоматически.

Для реальной загрузки нужны существующий бакет и настройки API: `S3_BUCKET`, `S3_ENDPOINT`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`. Для MinIO сначала создайте бакет через консоль на порту 9001. Если API работает в Compose, endpoint обычно `http://minio:9000`; для API на хосте — `http://127.0.0.1:9000`. При отсутствии настроек API вернёт понятную ошибку 503, остальные маршруты продолжат работать.
